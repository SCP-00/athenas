# Execution Laboratory Architecture v2

## Principios

1. **El laboratorio no decide** — Solo ejecuta exactamente lo que recibe.
2. **La unidad es el Experiment** — Un objeto único, no parámetros sueltos.
3. **Toda ejecución es reproducible** — Hash de modelo, prompt, seed, configuración.
4. **Runtime identity > Runtime path** — Se identifica por familia, variante y commit.
5. **Preguntas científicas** — Todo experimento responde una pregunta concreta.

## 5. Component Interaction

```
Planner (decides what to test)
  │
  │  Generates Experiments based on Scientific Questions
  │  Each experiment has all controlled variables fixed
  │
  ▼
Experiment Queue (stores experiment IDs)
  │
  │  Queue processes experiments autonomously
  │  No human/agent intervention needed
  │
  ▼
Execution Laboratory (executes blindly, measures everything)
  │
  │  Receives: Experiment (complete definition)
  │  Executes: llama-server with EXACTLY those parameters
  │  Measures: VRAM, RAM, GPU, timing, OOM, crashes
  │  Returns: ExecutionResult (all measured, no estimates)
  │
  ▼
Artifact Store (persists everything)
  │
  │  Each experiment → directory with artifacts, metrics, telemetry
  │  Any agent can read without executing
  │
  ▼
Knowledge Database (accumulates evidence)
  │
  │  ExecutionResults → structured knowledge
  │  Planner queries to decide next experiments
  │  Questions get answered when evidence is sufficient
```

## 6. Implementation Plan

### Fase 1 — Experiment como unidad (priority: highest)

1. Refactor `ExecutionConfig` → `Experiment` (include RuntimeIdentity, prompt hash, seed)
2. Refactor `ExecutionTelemetry` → `ExecutionResult` (richer, with traces)
3. Refactor `ExecutionProbe::execute()` → accepts `&Experiment`, returns `ExecutionResult`
4. Update PHASE-0006 to use new Experiment structure

### Fase 2 — Runtime Identity (priority: high)

1. Add `RuntimeIdentity` struct with family, variant, commit, build_flags
2. Update Runtime Discovery to extract identity (not just path)
3. Detect family from binary path + `--version` output
4. Hash binary for reproducibility

### Fase 3 — Scientific Questions (priority: medium)

1. Add `ScientificQuestion` struct
2. Add `QuestionRegistry` to manage questions
3. Planner generates experiments from questions
4. Knowledge Database accumulates evidence until question is answerable

### Fase 4 — Queue stores Experiment IDs (priority: medium)

1. Refactor `Experiment` → store actual experiment config (not just model path)
2. Queue stores experiment IDs referencing the full config
3. Queue processes by reading config, executing, storing result
